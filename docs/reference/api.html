API 参考

先看这一句：这份文档不是 API 的完整定义， 完整定义在 trove serve 自带的 /v1/docs。 这一页给的是分类、鉴权方式与场景示例——手抄一遍端点必然与代码脱节。

活文档在哪

服务启动后打开 http://<host>:<port>/v1/docs，那是 FastAPI 自动生成的 OpenAPI 界面：每个端点的参数、请求体、响应模型都在那里， 且随代码实时更新。

app.py:204 docs_url

所有路由都在 /v1 前缀下。后端是纯 JSON API，不托管页面 （前端由独立容器发布，nginx 反代 /v1）。

鉴权

认证走 Bearer token。依赖分几个层次，按需叠加：

依赖作用
get_current_user解析 token → 用户
require_admin要求 admin 角色
require_scope要求 token 带某个 scope（如 query）
require_datasource校验对该数据源的授权
check_api_rate限流与日配额

deps.py:73 get_current_user deps.py:120 require_admin deps.py:156 require_datasource

注意有两类端点不走用户鉴权，这是刻意的：

端点为什么免鉴权
/v1/health探活必须能被编排系统直接调用
/v1/metrics抓取端通常不便于携带用户 token

SSE 是手写的，没有引入额外依赖

对话是流式的，用的是标准的 Server-Sent Events，但没有依赖 sse-starlette——一个几十行的辅助函数就够了。

「恢复」这个端点值得注意：HITL 暂停后，图是真的停在那个检查点上， 恢复不是重新跑一遍，而是从断点继续。

POST /v1/semantic/query 与对话链路走同一个语义层，但契约更严： 遇到软 MISS 不降级，直接返回 422。理由见 语义层 · 声明式 API—— 程序调用方无法判断哪些部分是权威的、哪些是模型补的。

关于 CORS

后端没有 CORSMiddleware。这不是遗漏：

  • 生产形态下前端与 /v1 同源（nginx 反代）。
  • 开发形态下由 Vite dev server 代理 /v1 到后端。

vite.config.ts:12 proxy

两种形态下浏览器视角都没有跨域。如果你想把前端部署到另一个域名， 需要在网关层处理，而不是期望后端开 CORS 头——当前后端不会发那些头。
