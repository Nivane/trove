配置参考

配置分三处：conf/agent.yml（全局）、.trove/datasources.yml （每个数据源）、以及环境变量。这一页把三处说明白，并指出一个常见的找错地方。

配置放在哪

文件管什么优先级
./conf/agent.yml 全局：模型、开关、记忆、评测 高
~/.trove/conf/agent.yml 同上，作为个人覆盖 低（前者优先）
.trove/datasources.yml 每个数据源：连接、检索参数 —
~/.trove/settings.db 管理台改的运行时设置 启动时合入

conf/agent.yml:1 搜索顺序 config.py:38 CONFIG_SEARCH_PATHS

最常见的找错地方

rrf_k、rrf_weights、rerank_backend、rerank_endpoint 不在 agent.yml 里——它们是每个数据源的配置， 写在各数据源条目下。

理由很自然：不同库的检索特性不同，一套全局权重不可能对谁都最优。这也正是 混合检索那套调参脚本产出「可以写回 datasources.yml」的原因。

authz 段：执行前的授权门

key默认说明
table_enforcement enforce 表级判定（A3）的档位：enforce 拒绝；warn 只记日志与指标、放行（存量部署的回退阀）
require_principal true 执行路径缺主体时拒绝；关掉等于整层强制点不装配

两个键都可以写在顶层或 agent: 段内，两种写法等价。

这个开关只影响表级判定。数据源级判定（A2，「这个用户能不能用这个源」） 与「必须有主体」（A1）不受它影响，恒为拒绝——读错这个开关只会让 A3 变宽， 不会把鉴权关掉。默认 enforce 是静态核验后的决定：用 A3 同源基准对三份 KB 的 650 条快径示例 SQL 逐条比对，违规 0 条——按语义模型走的查询本来就在声明内。 warn 是给「确有声明外查询」的存量部署的回退阀：放行但记下被挡的表， 先观察一段时间再切回 enforce。细节见安全。

masking 段：字段级脱敏

key默认说明
enabled true 是否装配脱敏节点；关掉只影响这一步，不改变任何声明
hash_salt_ref 空 部署级 salt 引用（env:NAME）；模型级 masking.hash_salt_ref 优先 
masking:
  enabled: true
  hash_salt_ref: env:TROVE_MASK_SALT

hash_salt_ref 是引用而不是值：salt 走环境变量， 不进 YAML、不进 git。两处都解析不出来而确有字段声明了 hash 模式时， 执行被拒绝——按设计不得降级为明文。

egress 段：模型数据出境治理

key默认说明
enabled true 整层开关。只作用于语义模型已声明 mask 的字段——没有声明的部署在工具回喂口逐字节不变
redact_tool_results true 是否在工具结果回喂模型前，按 mask 声明脱敏
allow_providers 空 模型 provider 白名单。空 = 全部允许；含 / = 精确模型名；不含 / = provider 前缀；* = 全部允许
audit true 每轮汇总写一条 llm.egress 审计（字段名与计数，不含值） 
egress:
  enabled: true
  redact_tool_results: true
  allow_providers: [openai, anthropic, deepseek]
  audit: true

这一组也可以写在 agent: 段内，两种写法等价；allow_providers 接受 YAML 数组或逗号分隔字符串（手写 YAML 两种都常见），条目小写去空白。 管理端设置页可以热改前三个键（egress.enabled / egress.redact_tool_results / egress.allow_providers）， 下一次模型调用生效；audit 只在配置文件里。

它与 masking 是两个接收方：masking 管交付给用户的结果， egress 管发给模型的观测。所以关掉 masking.enabled 不会打开工具回喂的脱敏，两个开关各自独立。细节见 安全 · 模型数据出境治理。

oidc 段：单点登录

key默认说明
enabledfalse总体开关；关闭时无新路由、无登录按钮、无网络调用
issuer空OIDC issuer，必须 https（loopback http 例外）；discovery 从它拼出
client_id空OAuth 客户端 id
client_secret_ref空只接受 env:NAME；这是引用不是值，密钥不进 YAML / git
redirect_uri空留空按请求 base URL 推导 /v1/auth/oidc/callback；显式配置必须 https
post_login_redirect/前端地址；token 与失败码都放在它的 fragment 里
scopesopenid email profile请求的 scope 串
groups_claimgroups从 ID token 的哪个 claim 读组列表
role_map空IdP group → admin / analyst / user；多个命中取最高权限
default_roleuser没有命中任何映射时的角色
auto_provisiontrue首登自动建号（零授权）；关闭时未绑定身份一律 not_provisioned
 
oidc:
  enabled: true
  issuer: https://idp.example.com
  client_id: trove
  client_secret_ref: env:TROVE_OIDC_SECRET
  redirect_uri: https://trove.example.com/v1/auth/oidc/callback
  post_login_redirect: /
  groups_claim: groups
  role_map:
    trove-admins: admin
    data-analysts: analyst
  default_role: user

同样可以写在 agent: 段内。这一组不在管理端设置白名单里： 它是部署级安全配置，管理端可热改 / 可回显的面不接纳密钥。配置写了 enabled: true 但自洽性检查不过（缺 issuer / client_id、issuer 非 https、 client_secret_ref 不是 env: 引用、角色名未知）时， SSO 保持关闭（路由 404）并在启动日志说明原因。 默认关闭的部署与「没有 oidc 段」逐字段一致。流程与角色映射细节见 安全 · 单点登录。
