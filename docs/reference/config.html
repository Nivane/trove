配置参考

配置分三处：conf/agent.yml（全局）、.trove/datasources.yml （每个数据源）、以及环境变量。这一页把三处说明白，并指出一个常见的找错地方。

配置放在哪

文件管什么优先级
./conf/agent.yml 全局：模型、开关、记忆、评测 高
~/.trove/conf/agent.yml 同上，作为个人覆盖 低（前者优先）
.trove/datasources.yml 每个数据源：连接、检索参数 —
~/.trove/settings.db 管理台改的运行时设置 启动时合入

conf/agent.yml:1 搜索顺序 config.py:38 CONFIG_SEARCH_PATHS

最常见的找错地方

rrf_k、rrf_weights、rerank_backend、rerank_endpoint 不在 agent.yml 里——它们是每个数据源的配置， 写在各数据源条目下。

理由很自然：不同库的检索特性不同，一套全局权重不可能对谁都最优。这也正是 混合检索那套调参脚本产出「可以写回 datasources.yml」的原因。

两个默认关闭的开关值得单独说： promotion 是「证据够了就自动把 pending 教训转正」， 默认关是为了保护人工门禁；profile_boost 是把用户画像 注入生成提示，默认关是因为画像的优先级最低、收益不确定。

conf/agent.yml:233 gate_enabled config.py:177 gate_enabled

--ci 模式下如果 gate_enabled 是 false，门会拒绝执行而不是放行—— 「门被关掉了」不该被 CI 读成「通过」。

authz 段：执行前的授权门

key默认说明
table_enforcement enforce 表级判定（A3）的档位：enforce 拒绝；warn 只记日志与指标、放行（存量部署的回退阀）
require_principal true 执行路径缺主体时拒绝；关掉等于整层强制点不装配

两个键都可以写在顶层或 agent: 段内，两种写法等价。

这个开关只影响表级判定。数据源级判定（A2，「这个用户能不能用这个源」） 与「必须有主体」（A1）不受它影响，恒为拒绝——读错这个开关只会让 A3 变宽， 不会把鉴权关掉。默认 warn 也不是心软：存量 grants 只到数据源级， 直接 enforce 会把正常查询大面积 403，先跑一段收集「哪些表会被拒」。 细节见安全。

masking 段：字段级脱敏

key默认说明
enabled true 是否装配脱敏节点；关掉只影响这一步，不改变任何声明
hash_salt_ref 空 部署级 salt 引用（env:NAME）；模型级 masking.hash_salt_ref 优先 
masking:
  enabled: true
  hash_salt_ref: env:TROVE_MASK_SALT

hash_salt_ref 是引用而不是值：salt 走环境变量， 不进 YAML、不进 git。两处都解析不出来而确有字段声明了 hash 模式时， 执行被拒绝——按设计不得降级为明文。
