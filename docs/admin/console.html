管理台总览

/admin 是每天的第一站：一屏回答三个问题—— 平台还健康吗、用户在怎么用、什么在等我处理。 全页一次聚合请求取数，每个数字都是去明细页的入口。

一屏怎么读

每个数字都带出处；取不到就说取不到

这一页是纯聚合视图，所有块从一个端点取数（GET /v1/admin/overview）。 两条披露纪律值得注意：块级降级——某个块取数失败会显示该块的失败卡片与原因， 不会用 0 冒充；计数到顶会标注——扫描样本触顶时显示「到顶」或「样本到顶，计数为下界」， 精确计数与下界计数不混为一谈。

待办队列：八类来源，一个入口

队列把散在各页的待处理事项聚成一处，这样「今天该做什么」不用翻六个页面。 八类来源：KB 教训、KB 示例、语义草稿、技能草稿、 记忆偏好草稿、漂移条目、失败任务、待授权用户。

建议的日常节奏

  1. 1

    上班第一眼：横幅 + KPI

    横幅不是绿色或成功率明显下跌，先处理健康问题再看别的—— 后面所有数字的可信度都建立在数据源可达的前提上。

  2. 2

    清待办队列

    草案类（KB 教训 / 示例 / 语义 / 技能 / 偏好）决定知识库的口径积累速度， 建议当天清；审批入口见知识库运营与方法论技能。

  3. 3

    抽查最近事件

    队列全绿时可从「最近事件」随机点开几条，看有没有不该出现的动作—— 审计页的完整过滤在审计日志。
