Agent 能力总览

首页的十二组能力在这里展开成可执行的细节。 组织逻辑是四层：模型能碰什么（工具治理）、模型怎么被驱动（循环与预算）、 跑砸了怎么办（时间旅行与回滚）、跨会话留下什么（记忆与技能）。

四层，不是一个循环

大多数「Text2SQL Agent」的叙事是一句话：让模型调用工具、自己纠错、直到满意。这句话是对的， 但它描述的是第二层。一个能长期跑在生产上的问数 Agent，四层缺一不可—— 而且越往下越不该交给模型。

层要解决的问题确定性占比
① 工具治理 模型能看见哪些工具、越权时发生什么 全部——注册与裁剪在构图时完成，运行期零判断
② 循环与预算 怎么驱动、什么时候停、烧多少 骨架确定，停止条件交给模型
③ 时间旅行与回滚 这一轮改坏了，怎么回到上一轮 全部——版本比对与回滚是纯代码
④ 记忆与技能 跨会话留下什么、下次怎么用上 检索是确定性的，写入要过人工确认
一条贯穿全站的原则

能把判断变成代码的地方，就不要变成提示词。这不是「不信任模型」，而是：确定性规则可解释、可回归测试、且换模型不退化。

所以 join 路径由语义层算、结果对不对由规则链判、这一轮有没有进步由版本比对判——模型只负责它真正不可替代的那件事：把一句话理解成一个查询意图。

① 工具治理：越权不是一道墙，是「没有这个工具」

每个工具在注册时声明自己需要什么权限级别、对哪些角色可见。这份定义在交给模型之前 就按角色裁剪过了：

agent_loop.py:138 ToolSpec agent_loop.py:183 visible_to agent_loop.py:206 ToolRegistry

有意思的是越权时发生什么。运行时不会返回「权限不足」—— 那样等于告诉模型「这里有一扇门，只是你没钥匙」，而模型会开始试探。 它把越权调用折叠成「未知工具」：

agent_loop.py:519 visible_to

模型看到的是「没有这个工具」，于是它换一条路，而不是在墙上撞。这是一个小设计， 但它决定了权限系统是「引导」还是「对抗」。

工具清单按档位懒注册

工具不是一次性全给。简单问题只给 SQL 语法校验和收工工具，标准/复杂档才解锁只读执行探测与规则链校验； 能以只读方式摸到物理 schema 的三个枚举/结构/执行计划工具，还额外要求 analyst 或 admin 角色。 完整清单与各自的注册条件见 LLM 网关 · 工具注册表。

gen_sql.py:1036 build_sql_registry

② 生成循环：护栏不是停止条件

生成节点走一个 ReAct 循环。关键的设计选择是：由模型自己决定什么时候收工， 而不是「跑到没有工具调用为止」或「跑满 N 轮」。

agent_loop.py:361 run_agent_loop agent_loop.py:369 max_rounds

max_rounds 是护栏而不是目标：正常收敛的循环根本碰不到它。真正让模型停下来的， 是它调用 finish 把最终 SQL 作为载荷交出来——见下面的收工协议。

任何一道触顶，或者循环空手而归，都会降级回经典子图——「生成 → 校验 → 重试」 那条确定性的老路。所以 agentic 循环是加速器而不是单点依赖：它失灵时系统还在，只是慢一点。

收工协议：为什么要有 finish

靠「模型不再调用工具了」来判断结束是脆的：模型可能只是忘了、或者话说了一半。 所以这里把收工做成一个显式工具，模型必须把 SQL 作为参数交出来， 而且载荷要过校验才被接受。

agent_loop.py:253 add_finish_tool agent_loop.py:302 validate_finish

好处是「结束」变成了一个有内容、可校验、可记录的事件，而不是一个静默的推断。

④ 多候选与共识投票

对中等以上复杂度的问题，图上会并行跑多个候选子代理，各自生成一份 SQL，然后由共识节点 实际执行并投票——全票一致就直接采用，单一多数采用多数，分裂则带着分歧点回炉。

投票看的是执行结果而不是 SQL 文本。两份写法不同但结果一致的 SQL，在这个判据下是同一票—— 这正是我们想要的：要的是对的数据，不是对的字面。

顺带的一个细节：相似问法会轮换少样本示例。否则每次都从同一个角度切入，候选之间的多样性会塌掉， 投票也就失去了意义。

⑤ 检查点与时间旅行

每一步都落检查点，落哪种存储由后端决定——PostgreSQL 生产环境走 AsyncPostgresSaver， 本地与测试走 SQLite。

这让「回放任意一步」成为可能：出问题时不必猜，直接从某个检查点重放， 看当时模型拿到的是什么上下文、工具返回了什么。

这解决的是可解释性的最后一公里

「这个数字是怎么算出来的」有很多层答案：SQL 在这里、规则链的判定在这里、语义层的口径在这里。但「当时它为什么这么想」只能靠回放。

时间旅行是把 Agent 从「不可复现」变成「可复现」的那一步——没有它，剩下的可解释性都只是事后解释。

⑦ 人在环：默认拒绝

开启后，SQL 在执行前被拦下来交给人确认。这里有一条值得注意的默认值： 载荷认不出来就拒绝，而不是放行。

hitl.py:65 make_hitl

定时任务走同一条路，但自动放行——否则无人值守的任务会永远卡在确认上。 这两者的区别写在调度器里，不在提示词里。
